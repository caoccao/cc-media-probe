# ISO/IEC 11172-2: description from free sources

A description of the parts of ISO/IEC 11172-2 (*MPEG-1 video*, 1993) that the deliverables need, written for this project from free sources ([README](README.md)). It is not the standard.

## 1. Scope

The deliverables read the sequence header of MPEG-1 video: dimensions, aspect ratio, frame rate and bit rate.

## 2. Sequence header

The shared sequence header begins with `00 00 01 B3`. It carries 12-bit horizontal and vertical sizes, a four-bit aspect code, a four-bit frame-rate code, a bitrate field, a marker bit and a video buffer size. The constrained-parameters bit has meaning in MPEG-1 and must be zero in MPEG-2. Optional intra and non-intra quantization matrices affect where the header ends. [ITU-T H.262, sections 6.2.2.1 and 6.3.3](https://www.itu.int/rec/T-REC-H.262-201202-T!Amd4/en)

The first sequence header is immediately followed by a sequence extension in MPEG-2. If a complete sequence continues without that extension, H.262 section 6.3.1 identifies it as MPEG-1. If the input ends inside the header or before the following start code can be checked, the version is unresolved.

MPEG-1's `pel_aspect_ratio` describes sample shape. Its tabulated ratio is **height divided by width**. For example, code 1 means square samples and code 2 gives a height-to-width ratio of 0.6735. A width-to-height pixel aspect field needs the reciprocal. MPEG-2 uses the same bit position differently: code 1 denotes square samples and codes 2 through 4 denote display aspect ratios. [H.262, table 6-3 and annex D.9.8](https://www.itu.int/rec/T-REC-H.262-201202-T!Amd4/en) · [National Tsing Hua University course material, table 8.2](https://www.cs.nthu.edu.tw/~sheu/CS6570/Compression.pdf)

## Gaps

- H.262 identifies the MPEG-1 aspect field but omits its lookup table. G1.6 approved the course table (`nthu-cs6570-compression`) as a descriptive source for it. Keep an unverified or reserved code unresolved.
