# ISO/IEC 14496-30: description from free sources

A description of the parts of ISO/IEC 14496-30 (*timed text and other visual overlays in ISO base media file format*, 2018) that the deliverables need, written for this project from free sources ([README](README.md)). It is not the standard.

## 1. Scope

The deliverables need two things from this standard: the WebVTT header text that an MP4 track carries (plan section 4.3, "WebVTT: header text carried by the container"), and the identification of TTML tracks.

## 2. WebVTT sample entry

Source: `w3c-breakouts-2025-mse-text-tracks`, a talk given at W3C's Breakouts Day 2025 (a community source). Sample entry codes in `mp4ra-sample-entries`.

- The sample entry `wvtt` holds a WebVTT configuration box, `vttC`, whose content is a string: the WebVTT file header, that is the first line with `WEBVTT` and any style sheets and regions (`w3c-webvtt` defines that text).
- It may also hold a source label box, `vlab`, whose string tells apart cues of different movies.
- A sample is either an empty cue box (`vtte`), or one or more cue boxes (`vttc`) with optional additional boxes (`vtta`). The project reads the header only, not the cues.

## 3. TTML

TTML tracks use the sample entry `stpp` (`mp4ra-sample-entries`), which identifies them; their documents are not read (plan section 4.3, identification only by design).

## Gaps

- The exact field layout of `vttC` and `vlab` (plain box or full box, string termination) is not in the source. The header text is therefore read as the payload of the box, up to its end, decoded as UTF-8 (`w3c-webvtt`), and any trailing NUL is dropped.
- The fields of the `stpp` sample entry (namespace, schema location, MIME types) are not read.

## Sources
