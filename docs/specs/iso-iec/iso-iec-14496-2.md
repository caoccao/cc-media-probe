# ISO/IEC 14496-2: description from free sources

A description of the parts of ISO/IEC 14496-2 (*Coding of audio-visual objects — Part 2: Visual*, 2004) that the deliverables need, written for this project from free sources ([README](README.md)). It is not the standard.

## 1. Scope

The deliverables of plan section 4.3 parse the visual object sequence and video object layer headers of MPEG-4 Visual streams: profile and level, dimensions, pixel aspect ratio, frame rate and scan type. They appear in Matroska frames, as MP4 decoder-specific information ([iso-iec-14496-1.md](iso-iec-14496-1.md)), in AVI chunks, in transport and program streams, and in raw files.

## 2. What the free sources establish

- MPEG-4 Part 2 Visual has object type indication `0x20`. In MP4 the sample entry `mp4v` identifies a visual stream family. Use the object type to identify the codec. The combined profile-and-level indication can further qualify that stream. [RFC 6381, section 3.3](https://www.rfc-editor.org/rfc/rfc6381#section-3.3) · [MP4RA object types](https://mp4ra.org/registered-types/object-types)
- RFC 6416 gives an elementary-stream configuration beginning with `00 00 01 B0 01`. In this example the sequence start code is followed by the profile-and-level byte for Simple Profile, Level 1. A visual object and video object layer follow. The RTP example's 90 kHz clock describes timestamps and supplies no picture rate. [RFC 6416, sections 3.1 and 7.2.1](https://www.rfc-editor.org/rfc/rfc6416#section-7.2.1)
- Matroska declares MPEG-4 Part 2 codec IDs. AVI uses a FourCC whose mapping must be established for the particular identifier. These declarations can identify a container track when the elementary-stream configuration is missing.

## Gaps

- The RFC example identifies one configuration. It supplies neither a complete profile table nor all conditional video object layer fields for dimensions, pixel aspect ratio, timing or interlace. Report container-declared values with their provenance while the remaining header mappings await G1.6. A filename extension is only a hint for raw detection. Require matching stream evidence before reporting MPEG-4 Visual.
