# ISO/IEC 11172-1: description from free sources

A description of the parts of ISO/IEC 11172-1 (*MPEG-1 systems*, 1993) that the deliverables need, written for this project from free sources ([README](README.md)). It is not the standard.

## 1. Scope

MPEG-1 program streams (`mpg` files of the MPEG-1 era) differ from MPEG-2 program streams in their pack header. The prober must tell the two apart and read the system clock reference and the stream identifiers of the packets.

## 2. What the free sources establish

Both pack formats start with `00 00 01 BA`. In the MPEG-1 example in Technical Corrigendum 2, the next four bits are `0010`. The 33-bit system clock reference (SCR) follows in groups of 3, 15 and 15 bits, each followed by a marker bit of one. The remaining three bytes carry a 22-bit mux rate between two more set marker bits. The SCR counts 90 kHz ticks. The example also shows packet stream IDs for audio, video and padding. [ISO/IEC 11172-1:1993/Cor.2, corrected annex A example](https://cdn.standards.iteh.ai/samples/32094/259d3fc6cdcb4ff5b955070ac479a5e8/ISO-IEC-11172-1-1993-Cor-2-1999.pdf)

The MPEG-2 pack starts with the two bits `01` and carries both an SCR base and an extension. The reader must validate the corresponding header and its marker bits before assigning a version or reporting a clock. A short header or an invalid marker leaves the version unresolved. [ITU-T H.222.0, program stream pack syntax](https://www.itu.int/rec/T-REC-H.222.0/en)

## Gaps

- The corrigendum supplies a worked MPEG-1 pack and selected packet IDs. A general MPEG-1 packet parser, including all optional packet header fields, still needs supporting text at G1.6. An MPEG-2 PES extension field does not establish the MPEG-1 packet layout.
