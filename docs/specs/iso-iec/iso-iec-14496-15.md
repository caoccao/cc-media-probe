# ISO/IEC 14496-15: description from free sources

A description of the parts of ISO/IEC 14496-15 (*carriage of NAL-unit structured video in the ISO base media file format*, 2024) that the deliverables need, written for this project from free sources ([README](README.md)). It is not the standard.

## 1. Scope

The MP4 sample entries for AVC, HEVC and VVC carry decoder configuration in the `avcC`, `hvcC` and `vvcC` boxes, respectively. The parameter sets carried in these records use the NAL unit syntax of ITU-T H.264, H.265 and H.266. Sources include `iso-iec-14496-15`, `apple-quicktime-file-format` and the three ITU-T entries listed below.

Matroska carries the respective configuration record in `CodecPrivate`. Its AVC mapping also permits a legacy `mvcC` extension block after the record. Adobe's FLV 10.1 sequence header carries an AVC record. Enhanced RTMP v2 separately specifies sequence-start records for AVC, HEVC and VVC. See `ietf-draft-cellar-codec` §§3.3.9, 3.3.10 and 3.3.13, `adobe-flv-f4v-10-1` Annex E (`AVCVIDEOPACKET`), and `veovera-enhanced-rtmp-v2` (video tag body, `SequenceStart`).

## 2. AVC decoder configuration record

The field widths below come from the AVC section of the community source `yohhoy-isobmff-notes`. Apple identifies the record carried by the [AVC decoder configuration atom](https://developer.apple.com/documentation/quicktime-file-format/avc_decoder_configuration_atom) (`apple-quicktime-file-format`). The record begins on a byte boundary. Adjacent bit fields share bytes, and multi-byte lengths are big-endian.

| Field | Bits | Meaning |
|---|---|---|
| `configurationVersion` | 8 | 1 |
| `AVCProfileIndication` | 8 | Profile indication for the configuration |
| `profile_compatibility` | 8 | Compatibility byte, including the constraint-set flags and reserved bits (RFC 6381 §3.3) |
| `AVCLevelIndication` | 8 | Level indication for the configuration |
| reserved | 6 | All ones |
| `lengthSizeMinusOne` | 2 | Size in bytes of the length field before each NAL unit of a sample, minus one; 0, 1 or 3 |
| reserved | 3 | All ones |
| `numOfSequenceParameterSets` | 5 | Number of sequence parameter sets that follow |
| `sequenceParameterSetLength`, `sequenceParameterSetNALUnit` | 16, then that many bytes | Each sequence parameter set, a complete NAL unit |
| `numOfPictureParameterSets` | 8 | Number of picture parameter sets that follow |
| `pictureParameterSetLength`, `pictureParameterSetNALUnit` | 16, then that many bytes | Each picture parameter set |

The community notes show an extension for profile indications 100, 110, 122 and 144. It records `chroma_format` in 2 bits and `bit_depth_luma_minus8` and `bit_depth_chroma_minus8` in 3 bits each. The preceding 6, 5 and 5 reserved bits are all ones. An 8-bit `numOfSequenceParameterSetExt` follows, with a 16-bit length for each extension NAL unit. The notes do not establish the complete profile condition for the 2024 edition. When extension fields are unavailable, the probe can derive these properties from a readable SPS according to `itu-t-h-264` §§7.3.2.1 and 7.4.2.1.

## 3. HEVC decoder configuration record

Source: `yohhoy-isobmff-notes`. Big-endian, byte-aligned.

| Field | Bits | Meaning |
|---|---|---|
| `configurationVersion` | 8 | 1 |
| `general_profile_space` | 2 | As in the profile-tier-level structure of ITU-T H.265 |
| `general_tier_flag` | 1 | As in H.265 |
| `general_profile_idc` | 5 | As in H.265 |
| `general_profile_compatibility_flags` | 32 | As in H.265 |
| `general_constraint_indicator_flags` | 48 | As in H.265 |
| `general_level_idc` | 8 | As in H.265 |
| reserved | 4 | All ones |
| `min_spatial_segmentation_idc` | 12 | |
| reserved | 6 | All ones |
| `parallelismType` | 2 | |
| reserved | 6 | All ones |
| `chromaFormat` | 2 | `chroma_format_idc` |
| reserved | 5 | All ones |
| `bitDepthLumaMinus8` | 3 | |
| reserved | 5 | All ones |
| `bitDepthChromaMinus8` | 3 | |
| `avgFrameRate` | 16 | |
| `constantFrameRate` | 2 | |
| `numTemporalLayers` | 3 | |
| `temporalIdNested` | 1 | |
| `lengthSizeMinusOne` | 2 | As in section 2 |
| `numOfArrays` | 8 | Number of arrays of NAL units that follow |

Each array: `array_completeness` (1), a reserved bit (0), `NAL_unit_type` (6), `numNalus` (16), then `numNalus` NAL units, each with a 16-bit `nalUnitLength`. The arrays hold the video, sequence and picture parameter sets, and SEI messages.

## 4. Length-prefixed samples

For the AVC and HEVC sample formats described above, read each NAL unit's unsigned big-endian length using the width signaled by the applicable configuration record, then read that many bytes. The length excludes its own prefix. Inside the configuration record, the parameter-set and array entries have their own 16-bit lengths. Matroska's mappings refer to the corresponding Part 15 picture representation. See `yohhoy-isobmff-notes` and `ietf-draft-cellar-codec` §§3.3.9 and 3.3.13.

For legacy FLV, Adobe Annex E describes AVC packets (`adobe-flv-f4v-10-1`). For HEVC in Enhanced FLV, the `ExVideoTagBody` carries the configuration record in `SequenceStart`. A `CodedFrames` packet carries a signed 24-bit composition time offset in milliseconds before the HEVC data. A `CodedFramesX` packet omits that field and implies a zero offset. [Enhanced RTMP v2, ExVideoTagBody](https://github.com/veovera/enhanced-rtmp/blob/40589eb9d38d6555e6cdbbfc5699312995203561/docs/enhanced/enhanced-rtmp-v2.md#L1321-L1423)

For AVC, `avc1` carries SPS/PPS out of band and `avc3` permits them in samples (`w3c-mse-byte-stream-format-isobmff`, initialization segments). The `mp4ra-sample-entries` registry describes `hvc1` and `vvc1` as carrying parameter sets only in the sample entry, while `hev1` and `vvi1` also permit them in samples. See the VVC framing limit below.

## Gaps

- **VVC.** The stored Matroska and Enhanced RTMP mappings identify the VVC configuration record by reference to Part 15. They do not supply its field layout. Until a layout source is approved, the probe keeps the container-declared values and reads in-band parameter sets only if their NAL boundaries are independently known. A `vvi1` entry alone does not supply the NAL-length width. The NAL header and parameter-set syntax come from `itu-t-h-266` §7.3.
- **Further structures of the standard** (sample groups, extractors, the layered and multi-view records) are not needed by the deliverables.
