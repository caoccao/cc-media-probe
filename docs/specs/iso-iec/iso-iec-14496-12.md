# ISO/IEC 14496-12: description from free sources

A description of the parts of ISO/IEC 14496-12 (*ISO base media file format*, 2026) that the deliverables need, written for this project from free sources ([README](README.md)). It is not the standard.

## 1. Scope

ISO/IEC 14496-12:2026 is the eighth edition. MP4, 3GP, 3G2 and F4V use this family of file formats. Apple's QuickTime documentation describes the related MOV atoms. The sources below identify which ISO-family profiles document each field. A shared four-character code alone does not establish identical fields or version rules. See [the ISO catalog](https://www.iso.org/standard/85596.html), [the MP4 description](iso-iec-14496-14.md), `3gpp-ts-26244` clause 4, `3gpp2-c-s0050-b` clause 8, and `adobe-flv-f4v-10-1` §§1.1–1.4.

## 2. Box structure

Read these fields in order, most significant byte first. Sources are `apple-quicktime-file-format` (“Atoms”), `adobe-flv-f4v-10-1` §§1.3 and 3.2, and `mp4ra-boxes` (the `uuid` registration).

| Field | Bits | Meaning |
|---|---|---|
| `size` | 32 | Total bytes including the header. Zero extends to the end of the file. One selects the extended size below. |
| `type` | 32 | Box type, usually written as four characters. |
| `largesize` | 64 | Total bytes including the header when `size` is one. |
| `usertype` | 128 | Extended identifier when `type` is `uuid`. It follows `largesize` when both are present. |

A full box continues with an 8-bit `version` and 24-bit `flags`. Each box defines the effect of its version. For `mvhd`, `tkhd` and `mdhd`, version 1 widens the creation time, modification time and duration from 32 to 64 bits. In `sidx` it widens `earliest_presentation_time` and `first_offset`, while each `subsegment_duration` stays 32 bits. See `adobe-flv-f4v-10-1` §§2.4, 2.5.1 and 2.6.1 and `3gpp-ts-26244` clause 13.4.

## 3. Boxes and their sources

| Box | What the prober reads | Source |
|---|---|---|
| `ftyp` | Major brand, minor version, compatible brands | `apple-quicktime-file-format` ("File type compatibility atom"); brands in `mp4ra-brands` |
| `moov`, `trak`, `mdia`, `minf`, `stbl`, `edts`, `udta` | Containers | `apple-quicktime-file-format` |
| `mvhd` | Time scale, duration | `apple-quicktime-file-format` ("Movie header atom") |
| `tkhd` | Track ID, flags, duration in movie timescale units, presentation width and height | `apple-quicktime-file-format` ("Track header atom"), `adobe-flv-f4v-10-1` §2.5.1 |
| `elst` | Each edit gives a duration in the movie timescale and a start time in the media timescale. A media time of −1 denotes an empty edit. | `apple-quicktime-file-format` ("Edit list atom"), `adobe-flv-f4v-10-1` §2.5.2.1 |
| `mdhd` | Media timescale, media duration and language. The ISO-family language field has one zero bit and three 5-bit values. Adding 0x60 to each yields the three lowercase letters of the ISO 639-2/T code. | `adobe-flv-f4v-10-1` §2.6.1 for the encoding, `loc-iso-639-2` for the code list. MOV language conventions are described in `apple-quicktime-file-format` (“Media header atom”). |
| `hdlr` | Handler type (`vide`, `soun`, `text`, `subt`, `meta` and others) | `apple-quicktime-file-format` ("Handler reference atom"); handlers in `mp4ra-handlers` |
| `stsd` | Sample entries, their media-specific fields and codec configuration. A track can contain more than one description. | `apple-quicktime-file-format` (“Sample description atom”), `3gpp-ts-26244` clauses 6.2–6.3 and 6.5–6.8, and `mp4ra-sample-entries` for registered codes |
| `stts`, `ctts`, `stsc`, `stsz`, `stco`, `co64`, `stss` | Sample timing, composition offsets, chunking, sizes, offsets, sync samples | `apple-quicktime-file-format` (the atoms of the same names) |
| `colr`, `pasp`, `clap` | Color description, pixel aspect ratio, clean aperture. The `nclx` color description carries primaries, transfer characteristics, matrix coefficients and a full-range flag. | `apple-quicktime-file-format`, [`aom-av1-isobmff` §2.3.4](https://aomediacodec.github.io/av1-isobmff/v1.3.0.html#av1codecconfigurationbox-semantics) for `nclx`, and `itu-t-h-273` for the color code points |
| `sidx` | One reference track and its timescale. Entries can point to media or a subordinate index. Summing a parent and its children would count the same interval twice. | `3gpp-ts-26244` clause 13.4 |
| `tfdt` | Decode time of the fragment's first sample, in the track's media timescale. Version 0 uses 32 bits and version 1 uses 64 bits. | `3gpp-ts-26244` clause 13.5 |
| `mvex`, `mehd`, `trex` | Fragment declarations in the movie. Optional `mehd` supplies a duration in movie timescale units. Each `trex` supplies a track's default sample description index, duration, size and flags. | `adobe-flv-f4v-10-1` §2.9 |
| `moof`, `mfhd`, `traf`, `tfhd`, `trun` | The movie fragment has a sequence number. Each track fragment identifies a track and can override its defaults. A run gives a sample count and, according to its flags, a data offset, flags for the first sample, and per-sample fields. | `adobe-flv-f4v-10-1` §2.12 for the F4V layouts |
| `mfra`, `tfra`, `mfro` | Per-track random-access entries locate samples by time, movie fragment offset and track fragment, run and sample numbers. The trailing `mfro` gives the enclosing `mfra` size. An indexed access time alone does not establish the end of presentation. | `adobe-flv-f4v-10-1` §2.16 |

A later ISO final draft gives the version distinction for the optional per-sample composition time offset in `trun`: version 0 uses an unsigned 32-bit value and version 1 uses a signed 32-bit value. A negative offset affects composition time. It does not shorten the sample's decode duration. [ISO/IEC 14496-12:2008/FDAmd.3, proposed revision to clause 8.8.8.2](https://cdn.standards.iteh.ai/samples/59147/f674c7550479443f9e3b6f2047105a99/ISO-IEC-14496-12-2008-FDAmd-3.pdf)

For the W3C Media Source Extensions profile, the initialization segment is an `ftyp` and a `moov` containing `mvex`. A media segment has an optional `styp`, one `moof` and one or more `mdat` boxes. The profile requires a `tfdt` in each track fragment and movie-fragment-relative addressing. These are conditions on that streaming profile. [W3C byte stream format, §§3–4](https://www.w3.org/TR/2026/NOTE-mse-byte-stream-format-isobmff-20261109/)

## Gaps

- **Movie fragments outside the documented profiles.** Adobe's tables describe F4V and refer to the 2008 ISO edition. For example, its run table documents unsigned composition offsets. W3C supplies segment constraints but delegates the general box syntax to ISO. The historical ISO draft in section 3 provides evidence for signed `trun` offsets. Confirm the applicable versions and defaults before using a layout beyond the documented profiles at G1.6. The project leaves derived fragment durations and sample counts unavailable until the relevant syntax and defaults have an approved source.
- **Compact sample sizes.** `mp4ra-boxes` registers `stz2`; the QuickTime sample-size table cited above describes `stsz`. Verify the packed `stz2` entry layout before using it to locate samples.
- **Item-based files** (`meta` with `iloc`, `iinf`) are not needed by the deliverables.
