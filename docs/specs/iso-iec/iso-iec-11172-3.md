# ISO/IEC 11172-3: description from free sources

A description of the parts of ISO/IEC 11172-3 (*MPEG-1 audio*, 1993) that the deliverables need, written for this project from free sources ([README](README.md)). It is not the standard.

## 1. Scope

Every MPEG audio frame (layers I, II and III, the formats of `mp1`, `mp2` and `mp3` files) starts with a 32-bit header. The project reads it in raw files and in every container that carries MPEG audio. The lower sampling rates added by MPEG-2 are in [iso-iec-13818-3.md](iso-iec-13818-3.md).

## 2. Frame header

Source: `mp3-tech-frame-header`, a community source. Fields are in wire order, most significant bit first. The 11-bit sync and two-bit version notation accommodates the non-ISO MPEG 2.5 extension. For ISO MPEG-1 and MPEG-2, the first 12 bits are all ones and the following ID bit distinguishes the two.

| Field | Bits | Meaning |
|---|---|---|
| Frame sync | 11 | All ones |
| Version | 2 | 3 MPEG-1, 2 MPEG-2, 0 the later "MPEG 2.5" extension, 1 reserved |
| Layer | 2 | 3 layer I, 2 layer II, 1 layer III, 0 reserved |
| Protection bit | 1 | 0 when a 16-bit CRC follows the header |
| Bit rate index | 4 | Section 3; 0 is free format, 15 is not allowed |
| Sampling rate index | 2 | Section 4; 3 is reserved |
| Padding bit | 1 | When set, the frame has one extra slot of 4 bytes in layer I, 1 byte in layers II and III |
| Private bit | 1 | Available for private use |
| Channel mode | 2 | 0 stereo, 1 joint stereo, 2 dual channel, 3 single channel |
| Mode extension | 2 | Joint stereo only |
| Copyright, original | 1 each | |
| Emphasis | 2 | 0 none, 1 50/15 µs, 3 CCITT J.17, 2 reserved |

## 3. Bit rates

In kilobits per second, by index 1 to 14 (`mp3-tech-frame-header`):

| Index | MPEG-1 layer I | MPEG-1 layer II | MPEG-1 layer III | MPEG-2 and 2.5 layer I | MPEG-2 and 2.5 layers II and III |
|---|---|---|---|---|---|
| 1 | 32 | 32 | 32 | 32 | 8 |
| 2 | 64 | 48 | 40 | 48 | 16 |
| 3 | 96 | 56 | 48 | 56 | 24 |
| 4 | 128 | 64 | 56 | 64 | 32 |
| 5 | 160 | 80 | 64 | 80 | 40 |
| 6 | 192 | 96 | 80 | 96 | 48 |
| 7 | 224 | 112 | 96 | 112 | 56 |
| 8 | 256 | 128 | 112 | 128 | 64 |
| 9 | 288 | 160 | 128 | 144 | 80 |
| 10 | 320 | 192 | 160 | 160 | 96 |
| 11 | 352 | 224 | 192 | 176 | 112 |
| 12 | 384 | 256 | 224 | 192 | 128 |
| 13 | 416 | 320 | 256 | 224 | 144 |
| 14 | 448 | 384 | 320 | 256 | 160 |

For MPEG-1 Layer II, 32, 48, 56 and 80 kbit/s are valid only in single-channel mode. Rates of 224, 256, 320 and 384 kbit/s require a two-channel mode (`mp3-tech-frame-header`). A valid index alone is insufficient to validate the header.

## 4. Sampling rates

By index 0, 1, 2: MPEG-1 44100, 48000 and 32000 Hz; MPEG-2 22050, 24000 and 16000 Hz; MPEG 2.5 11025, 12000 and 8000 Hz (`mp3-tech-frame-header`).

## 5. Samples per frame

An MPEG-1 frame holds 384 samples per channel in Layer I and 1152 in Layers II and III. Given a bitrate `R` in bits per second, sample rate `f` in hertz and padding bit `p`, the frame length in bytes follows from the sample count and the slot sizes in section 2:

- Layer I uses four-byte slots: `4 × (floor(12 × R / f) + p)`.
- Layers II and III use one-byte slots: `floor(144 × R / f) + p`.

When locating raw audio, check a compatible header at the predicted boundary. VBR permits the bitrate to change between frames. Free-format index 0 supplies no bitrate for this calculation. Establish the spacing from repeated compatible headers, allowing for padding. A single sync pattern inside compressed data is ambiguous. [RFC 2250, section 3.2](https://www.rfc-editor.org/rfc/rfc2250#section-3.2)

## Gaps

- A truncated or isolated free-format frame can leave its length and bitrate unresolved.
- The side information and ancillary payload are outside this header description. `mp3-tech-info-tag` covers supported first-frame VBR metadata (plan section 4.3).
