# ISO/IEC 13818-7: description from free sources

A description of the parts of ISO/IEC 13818-7 (*Advanced Audio Coding (AAC)*, 2006) that the deliverables need, written for this project from free sources ([README](README.md)). It is not the standard.

## 1. Scope

An AAC stream can use ADTS framing, one header per transport frame, or ADIF, one header for the whole stream. A container can also carry AAC access units or LATM. In AVI, consult the declared AAC payload type before choosing a parser. [Microsoft AAC media types](https://learn.microsoft.com/en-us/windows/win32/medfound/aac-media-types)

## 2. ADTS header

Source: `multimedia-wiki-adts`, a community source (the page links to an implementation, which was not opened). Fields are read most-significant bit first.

| Field | Bits | Meaning |
|---|---|---|
| syncword | 12 | All ones (0xFFF) |
| ID | 1 | 0 for MPEG-4, 1 for MPEG-2 |
| layer | 2 | 0 |
| protection_absent | 1 | 1 when there is no CRC |
| profile | 2 | For MPEG-2, 0 Main, 1 LC, 2 SSR, 3 reserved. For MPEG-4, the value is the audio object type minus one for the types representable here |
| sampling_frequency_index | 4 | Use the indexed [sampling rates](iso-iec-14496-3.md). Index 12 (7350 Hz) is reserved for MPEG-2. Values 13 and 14 are reserved, and ADTS forbids the explicit-frequency escape 15 |
| private_bit | 1 | |
| channel_configuration | 3 | As in the AudioSpecificConfig; 0 means a program configuration element in the frame |
| original_copy, home | 1 each | |
| copyright_identification_bit, copyright_identification_start | 1 each | |
| frame_length | 13 | Length of the frame in bytes, header included |
| adts_buffer_fullness | 11 | 0x7FF for variable bit rate |
| number_of_raw_data_blocks_in_frame | 2 | Number of AAC raw data blocks minus one (one to four blocks) |

The fixed and variable headers together occupy seven bytes. An unprotected frame starts its payload there. A protected frame with one raw data block adds a two-byte CRC before that block. A protected frame with multiple blocks also carries block positions, a header CRC and per-block CRCs. The two-byte shortcut would read the wrong payload offset. Validate the complete frame length against these fields and the available input. [GOST R 54713-2011, ADTS error-check structures](https://normadocs.ru/gost_r_54713-2011) · [SMPTE ST 381-4, AAC frequency index table](https://www.drastic.tv/images/documentation/st0381-4-2017.pdf)

## 3. ADIF identification

The four ASCII bytes `ADIF` (`41 44 49 46`) identify a candidate at the start of the stream. The Library of Congress describes the optional copyright identifier, bitrate fields, program count and per-program configuration. A probe can recognize the signature without having enough data to report the program properties. [Library of Congress, AAC ADIF](https://www.loc.gov/preservation/digital/formats/fdd/fdd000112.shtml)

For MPEG-2 AAC, the program configuration element gives the sampling frequency index and lists the front, side, back and LFE elements for a program. For each front, side or back element, count one channel for a single-channel element and two for a pair, then add the LFE channels. A program count is not a channel count. Programs can share elements, so report each program separately. [GOST R 54713-2011, table 25 and clause 6.5.3.2](https://normadocs.ru/gost_r_54713-2011)

## Gaps

- Signature detection can use the four starting bytes. Extracting program properties also requires a complete, bounded configuration element. The national standard supplies candidate evidence for the Phase 11 metadata pair at G1.6. A truncated element leaves that program's properties unresolved.
