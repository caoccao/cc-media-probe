# Spike: the usage scenarios of the API specification

This disposable spike type-checks the usage scenarios of Phase 2, task 3 against the surface that the [API specification](../../docs/design/api.md) defines. Section 15 of the specification shows the scenarios; the code there is the code of `examples/` here, without the file headers. The spike is a workspace of its own, excluded from the root workspace, with its own lock file (plan section 7.1). Nothing in the root workspace depends on it, and it is deleted once the skeleton of task 11 exists.

## What it holds

- **A stub of the library** in `src/`, named `cc_media_probe` so that the scenarios read exactly as a caller writes them. Its types, accessors and entry points have the signatures of `api.md` sections 3 to 13, as far as the scenarios use them. Enums carry a subset of their variants. Nothing is parsed: every probe opens or touches its input and then returns an error.
- **The scenarios** in `examples/`, one program each. Three need a feature, as their shipped versions will: `export_json` needs `serde`, `probe_with_tokio` needs `tokio` and `probe_with_futures` needs `futures-io`.
- **Twenty-six test files** in `tests/`, two unit tests of the writer's positions in `src/document/writer.rs`, which start the count near 2^32 and near 2^53 − 1, and nine doc tests: seven of the catch-alls' payloads, four of which must fail to compile, and one of `IntegerValue`, which must fail to compile because it has no serialized form of its own, and since the nineteenth review one of `src/document/contents.rs`, which must fail to compile because no inherent `Generator::deserialize` stands beside the trait:
  - `archive.rs`, with the `serde` feature, holds the archive cases of the sixth and seventh reviews. A known shortfall rules out `ok` beside a status of a newer version, and a report never allows `error`. A path's display string, flag and raw data describe one path. Chapters and tags are flat arrays with parent positions, and a chain of 200,000 tags reads back with serde_json's default recursion limit. A standalone chapter or tag is the flat array of its subtree, with one root. A tag value is a map of its kind and the member named after it, and a kind of a newer version keeps its name. A bare report and a bare error record check their versions. A rational reads back only in its reduced form, and a twin only in its own range. A member that holds null fails in an entry and in a source entry.
  - `data_enums.rs`, with the `serde` feature, holds the cases of `TagValue` and `ChromaFormat`. The kind alone decides how the other members are read. A kind of a newer version reads whatever its members hold and writes them back in their order, `kind` first and each member by its value, so `1e0` comes back as `1.0`. A known kind ignores an unknown member, a kind without a value is its `kind` alone, and null or a member named twice fails. A binary size beyond 2^53 − 1 is its twin `size_exact`. Since the nineteenth review, a known kind reads its members as they come once `kind` is read, so the error of `{"kind":"integer","integer":"oops","extension":null}` comes before the null and keeps its line and column, while a member before the kind fails where the kind is read; a kind of a newer version keeps its members before and after the kind.
  - `forwarding.rs`, with the `serde` feature, holds the eighth review's case of an entry whose outcome a newer version wrote. It keeps the members that this version does not read, such as the `skip_reason` of an outcome `skipped`, and writes them back in their order, from the document read and from one rebuilt. An entry of a known outcome drops them, a kept null fails, and its records are still checked against the document's version. Since the ninth review, `with_outcome` refuses such an outcome while the entry as read forwards it, and a rebuilt document gives its version to every record under `report`, `detection` and `error`, while a kept member comes back as read.
  - `catch_alls.rs`, with the `serde` feature, holds the ninth review's cases of a catch-all's payload. A payload put back into its own enum reads back, and an entry takes only an outcome that this version knows. That a payload cannot move into another enum, or be read on its own, is shown by the doc tests of `src/model/unrecognized_value.rs`, `src/model/unrecognized_kind.rs` and `src/details/unrecognized_details.rs`.
  - `lookups.rs`, with the `serde` feature, holds the tenth review's case of the tag lookups, which see the top level only: a whole-file set whose only valued `TITLE` is inside `ORIGINAL` has no file title and no match for `tags_with_key`, and the first match is the first top-level tag in report order and stored order. Since the twelfth review, a set that a live stream's later Tags element superseded stays in `tag_sets()`, and no lookup sees it.
  - `agreement.rs`, with the `serde` feature, holds the twelfth review's case of a report whose reasons, first reasons and statuses disagree part by part, which reading refuses, alone and in a document, while a part or a status of a newer version agrees through the record.
  - `h264.rs`, with the `serde` feature, holds the twelfth review's case of the H.264 details: the picture parameter sets read, a set cut short after its own identifier, the identifiers that the first picture's activation named, and where each set came from.
  - `version_first.rs`, with the `serde` feature, holds the cases of Phase 2, task 5: each of the four root records reads its version wherever it stands, and gives the version error before a member that would not decode, written before and after the version, and without a version. A null fails in every member at any depth, an unknown one included, and a map that names a member twice fails, but neither before the version error, also beside a newer major version that wrote a null. A bare error record and a document check their nested records' versions, written last, and an error in a member after the version keeps its line. The stub's own records hold no null and read back. Since the thirteenth review it also shows that serde_json's own error for `1e400` comes before the version error, and that a parsed `Value` no longer shows a repeated name. Since the seventeenth review, an enum written as an object with a second member fails in either order.
  - `nested_versions.rs`, with the `serde` feature, holds the thirteenth review's case of nested versions: a nested record compares its version with that of the record that holds it before it decodes anything after it, so a nested error of version 1.1 whose message is `42`, or one of version 2.0 with a null after its version, gives the version error with the document's `results` before and after the document's version, and a bare error record's partial report the same. A null or a repeated name before the nested version is malformed in both orders. Since the fourteenth review, a reader's callback that reads a document of version 1.1 and a rational written as an array, while the outer document waits for its bytes, reads each in a scope of its own.
  - `standalone.rs`, with the `serde` feature, holds the thirteenth review's case of records read alone: `Rational`, `Usage`, `Diagnostic`, `LocalizedText` in a node of a tree and `Generator` refuse a null, a repeated name and an array of their values alike, alone and inside a document, and so do an error record's diagnostics and a tag value's binary member; a root record is never an array.
  - `consistency.rs`, with the `serde` feature, holds the fourteenth review's agreements: a known header state that is not final beside a headers status of a newer version needs the first reason of the headers and makes an entry `partial`; a part that a limit stopped first has its first reason, a limit reason finds its counter, the record keeps the declared order and no detail in a first reason; a stream's index is its position; and an error holds a partial report or observations, never both, with a partial report whose record is the error's.
  - `detections.rs`, with the `serde` feature, holds the fourteenth review's detections: each known outcome with its own members reads and gives its entry's outcome, an outcome without a member it needs or beside one of another outcome fails, an `ok` entry whose identified detection lacks its format fails, confidences lie from 0 to 100 and fall with the rank, an outcome of a newer version reads whatever it holds, and `bytes_needed` has its twin.

  - `root_versions.rs`, with the `serde` feature, holds the twelfth review's case of `schema_version()` on a bare report, detection and error record of a newer minor version, and on a record that a document holds. Since the thirteenth review, a bare report written again keeps the version that it was read with, while a record that this version built writes 1.0 and a document gives its records its own.
  - `flat_trees.rs`, with the `serde` feature, holds the ninth review's case of a flat tree out of depth-first order: a forest in that order reads back in its order, and a node that returns to a closed subtree fails, for tags and for chapters.
  - `payloads.rs`, with the `serde` feature, holds the fifteenth review's kept members and numbers: a detection of a newer outcome and an error record of a newer kind write back the members they do not read, alone and in a rebuilt document, while known ones drop them; and the private map of serde_json's `arbitrary_precision` feature, given as text, reads as its number before the version and in a kept member, `1e400` in it fails, and one that holds no number stays a map. Since the eighteenth review: a detection, an entry and an error record keep the members that they do not read, before their outcome and after it, in order, for an outcome of a newer version, pass them by for a known one, and still refuse a null inside one passed by.
  - `neutral_values.rs`, with the `serde` feature, holds the fifteenth review's map with integer names, given by a small self-describing reader of the test's own: before the version of a root record read alone it is held and the version error comes first, and after the version, before a nested record's version and in a member that no type reads, it fails as a value that JSON does not carry. Since the seventeenth review, its reader drops a tag on a typed request, as ciborium does, and the file holds a tag around a confidence and around a whole candidate, refused in either order and read alone, a tagged value and 2^64 before a nested record's version, refused in either order of the parent's members, and 2^64 in an entry of a newer outcome, refused with the form's own message. Since the eighteenth review: a tag around a whole detection, in either order, and around a document, a standalone `EntryOutcome`, `DetectionStatus` and `TagValue`, each refused.
  - `own_checks.rs`, with the `serde` feature, holds the fifteenth review's checks of a record's own members: a standalone candidate, reason and completeness are checked as inside a detection and a report; the omitted count covers every first reason that the kept reasons lack; only a source failure carries a partial report; and an error's limit reason finds its counter. Since the nineteenth review, a value and its provenance are present together, for a video's frame rate, an audio stream's channel count, and a stream's and a report's duration and bit rate.
  - `private_numbers.rs`, with the `serde` feature, holds the sixteenth review's private map of arbitrary precision, written as text: a typed member takes it as an object before the version as after it, a kept member as its number, and a member that no type reads refuses `1e400` in either order; a map of that name beside another member stays a map; and `1.2234567890123456789` comes back as the nearest double. Since the seventeenth review: the name refused in a `Disposition`, as one member or beside another, in either order and read alone; `1e400` before a nested record's version refused in either order of its parent's members; and a JSON integer beyond 64 bits written back as the nearest double where no type is known and refused as an entry's index.   - `bounds.rs` checks at compile time that the model, the error and the prober are `Send`, `Sync` and `'static`, and that the probe futures are `Send` for Tokio and for a boxed `Send` source.   - `async_source.rs` checks the repeated-request contract of section 9.3 against the stub. A source that answers `Pending` is asked again with the same position and buffer length.   - `document.rs`, with the `serde` feature, checks that a document has the wire form of `api.md` section 12 for every member the stub writes. It reads a document back and checks each entry through its getters. The stub builds no report, so its entries are error records, and a detection entry is written by hand. It also reads a usage-error document back. Reading refuses a document whose usage error stands beside results, an entry of a known outcome that lacks its record or holds one that does not warrant the outcome, a nested record of another version in any record of an entry or in the partial report of an error record, and a document of another major version. It also refuses raw path data of a known encoding that is not whole units of lowercase hexadecimal digits, and keeps a foreign path and the data of a newer encoding. An outcome from a newer version, and a detection outcome from a newer version, read back as written. The entries of plan section 8.9 read back as written there, a lossy input keeps its flag and raw form, a 32-bit identifier in an error's observations is a string, a document rebuilt from entries of version 1.1 gives them its version down to their partial reports, and an entry whose outcome this version cannot derive is refused and takes the outcome given.
  - `report.rs`, with the `serde` feature, reads six cases of a report from JSON. In the first, a limit stopped one candidate's check while another validated, so detection is incomplete, the record names detection, and the entry is `partial`. In the second, a first sample's description is known but was not kept: the codec is absent, there is no candidate, one is missing, and the ISO details keep the index. In the fourth, from the seventh review, the tags fell short under a full budget, and `is_complete()`, `Display` and the entry's outcome all say so. In the fifth and sixth, from the eighth review, the headers status carries the header states into completeness: reading refuses one that contradicts a known state, and beside a state of a newer version it is the writer's verdict. The third and fourth omitted counts are decimal strings, and a reason's member that holds null fails. Since the tenth review, a codec that the input never named displays as "a codec that was not read", and a companion's diagnostic names its source through `SourceIdentifier::value()` and `Display`. Since the eleventh review, an ISO description cut off before its format code displays as "a description that was not read", with `has_every_candidate()` false and the index in the details. Since the twelfth review, a codec of a newer version displays the serialized name that its version wrote, and an unknown codec without a raw identifier "an unknown codec".
  - `writer.rs`, with the `serde` feature, checks the document written as it goes: it writes what `Document::from_results` writes, for no entries and for mixed ones, down to the version of a partial report, takes an entry only after the previous one was written, and takes none after an output error.

The dependencies are the approved ones of the dependency dossier: Serde, Tokio with `fs`, futures-io, and as development dependencies `futures-lite`, `serde_json` and Tokio's runtime.

## Running it

In `spikes/api-scenarios/`:

- `cargo clippy --offline --all-targets -- -D warnings`, once with no feature, once with each feature alone, and once with `--all-features`;
- `cargo test --offline --all-features`;
- `cargo run --offline --all-features --example <name>` for any scenario. With no media file and no parser, each one ends with an ordinary error, never a panic.

From the repository root, `cargo run -q --locked -p cc-media-probe-checks -- structure --root spikes/api-scenarios` applies the structure rules of R30 to R33 and the header.
